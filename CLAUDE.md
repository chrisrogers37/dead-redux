# CLAUDE.md

Dead Redux features one Grateful Dead show a day and plays it in a three.js world. `README.md` describes the site and how to run it; `PROJECT_MISSION.md` says where it is going. This file holds the rules the repo already keeps, each cited to the test, script, workflow or record behind it.

## Checks

CI's three required checks (`.github/workflows/ci.yml`):

```sh
npm run lint        # Lint
npx tsc --noEmit    # Type-check
npm run test:run    # Unit tests: every vitest file in src/lib/__tests__/ and scripts/__tests__/
```

One file: `npx vitest run src/lib/__tests__/quality.test.ts`. The dev server sends no Content-Security-Policy (`src/proxy.ts`), so check anything the policy governs on a build or a preview.

## Where things are

- `src/app/`: the pages, the `/api/playing/<date>` route, the sitemap, `robots.txt` and the feed (`sitemap.ts`, `robots.ts`, `feed.xml/route.ts`), the icons and the share cards.
- `src/components/world/WorldHome.tsx`: the page around the world, its HUD, and the script tag that loads the world.
- `src/components/player/`: the audio player.
- `src/lib/`: the daily pick, the Relisten look-up, the site's address (`site.ts`), the sitemap's and the feed's entries (`feeds.ts`), the policy and the import map.
- `public/world/*.js`: the world, as plain ES modules outside the bundle. They import only each other and three.js. `trees.js` is the groves.
- `public/maps/<show date>.json`: one map per show.
- `data/shows.json`: the catalog. `data/pick-schedule.json`: every date's show.
- `scripts/`: the catalog refresh and the Maps workflow's scripts.
- `scripts/flash/`: the flash counter (`README.md` there).
- `src/lib/__tests__/` (the world's tests too) and `scripts/__tests__/`: vitest.
- `.github/workflows/`: `ci.yml`, `preview.yml`, `screenshots.yml`, `maps.yml`. `.github/screenshots/`: the shoot, with its own `package.json`.

## How a change lands

- Through a pull request off `main`. The repo's "Protect main" ruleset requires one, with Lint, Type-check and Unit tests passing and one approving review, and refuses force pushes and deletion.
- Small PRs, each with a code review and a review of its screenshots (#121).
- Every push to a PR's branch gets a Vercel preview, and the Screenshots workflow shoots it (`screenshots.yml`). It runs on the pull request, waits for the Preview status on the PR's head commit (`preview.yml`) and shoots the URL that status names; a pull request from a fork is not shot. The shoot is three jobs side by side, one for each shard: `desktop-acts`, the desktop's pages that click, press or play; `desktop-looks`, its pages that are only loaded and shot; and `rest`, every other device, the recordings and the generated images (`.github/screenshots/shards.mjs`; `scripts/__tests__/shoot-shards.test.ts`). Each job uploads an artifact named for its shard, and `gh run download <run>` makes a folder of each. The screenshot review reads the three folders together: every still and recording is in exactly one of them. A job fails when a still or a recording its plan names was not saved, as when a step is skipped because its control is absent, or when it saved a file the plan does not name (`planFailures`). A job that fails fails the run, and still uploads what it took.
- A device's pages share one browser, so a still can depend on the pages before it: a play step whose page names no `?at=` resumes where the day's show last played. The desktop's pages that act are shot together, in the list's order, so each finds what it does in a whole shoot. A page with only shots and near steps is shot apart from them, in a browser no page has acted in: a still that needs what an earlier page left belongs to a page that acts (`onlyLooks` in `shards.mjs`).
- Commit and PR titles start with the area they change, such as `world:`, `maps:`, `ci:` or `player:` (`git log`).

## three.js is pinned, by version and by hash

- three 0.185.0 loads from jsDelivr through the import map in `src/lib/import-map.ts`, which gives each file a sha384 digest. `import-map.test.ts` holds the map to exactly the files the world imports, at the version `package.json` installs for the tests (`devDependencies`).
- The Screenshots workflow fetches each pinned file, in each of its jobs, and fails when the CDN's copy doesn't match its digest.
- An upgrade changes the version in both places and every digest, in one PR.

## The Content-Security-Policy

- Each page gets a policy with a fresh nonce (`src/proxy.ts`, `src/lib/csp.ts`): scripts only from the site, the nonce and the pinned three.js files; media only from archive.org; connections only to the site. `security-headers.test.ts` pins the policy and the other headers (`next.config.ts`).
- The roadmap's arcs are "built in code, with no files from outside the site and no change to the security policy" (#121).

## Draw calls and the quality tiers

- Each tier has a draw-call budget a frame: desktop 70, phone 45, TV 60 (`CALL_BUDGET` in `.github/screenshots/assets.mjs`; `scripts/__tests__/screenshot-assets.test.ts`). The shoot fails when a shot's frame goes over, or the peak of its walk across the island (`?pose=sweep`) does.
- What repeats draws as one instanced or merged mesh: the crowd, the bears' legs, the rig's beams, the still landmarks, the trees, all of a kind as one, and the band's limbs and its still parts (`crowd.js`, `bears.js`, `rig.js`, `landmarks.js`, `trees.js`, `band.js`). A phone's trees add under 5,000 triangles to a frame (`trees.test.ts`). The band is eight draws at the most on every tier, for every line-up (`band.test.ts`, `band-lineups.test.ts`).
- The tier, desktop, phone or TV, is picked once at load (`pickTier` in `public/world/quality.js`), or by `?tier=`. It sets the render scale, the ground's grid, the sky's octaves, the bears, the field of view, shadows and the crowd (`BUDGETS`). A phone's and a TV's crowd is of plainer figures, 1,772 triangles each to a desktop's 2,765, every form of every part counted (`figureGeometry` in `crowd.js`; `crowd.test.ts`, `main.test.ts`).
- When the median of a 60-frame window is over 34 ms, the world steps down one rung, and never back up: the render scale down to half, then shadows, the sky's octaves, half the crowd, the bears, the stage light, the rig (`stepDown`; `quality.test.ts`). Windows drawn while the world loads don't count.

## Figures are faceless, and the beams never light them

- People are faceless figures, never anyone's likeness (#121). The band is the show's line-up, five to seven players, by the table in `lineup.js`, which gives each date of the band's years its roles from Wikipedia's list of the band's members: two guitars, a bass, one or two drummers, the era's keyboards and, from the end of 1971 to 1979 but for a leave at the end of 1973, a singer (`lineup.test.ts`). A line-up is roles, never people. The players are lit, in colour and faceless: a head is one smooth form in its skin, under its hair or a hat, with nothing on it. What a player wears, and the colours of their skin, hair and instrument, come from a generic palette for the show's era (the late sixties, the early seventies, the late seventies and the eighties, the nineties: `WARDROBES`), picked by the seat and the era alone (`dressOf`), so a seat wears something else in each era. The role picks which garments a player wears, a coat, a skirt or trousers (`DEAL`), and the seat and the era pick their colours; what a lead guitar shows on its shoulders, chest and sleeves, its coat and what shows down its front included, is never near-black. None pairs an instrument with the build and the hair a fan knows a player of it by, and nothing stands under a jaw, where an outline would read a beard (`band.js`; `band.test.ts`, `band-lineups.test.ts`). Each is shaped as a person, a torso with shoulders, a chest and a waist, a neck, a head shaped as a skull, arms with elbows, hands (the fretting hand and the singer's two closed on what they hold), legs with knees, and shoes, and is one piece from the front, the side and above, at rest and through a whole solo as the band plays, each hand where the role puts it, the legs under a skirt or a coat inside it as it hangs, and each foot on the floor (`band-bodies.test.ts`).
- The band has a light of its own, in its own shader, which three's lights do not reach: a key from the crowd's right, a fill from above and a warm edge on the sides turned to the panel (`LIGHT` in `band.js`). It takes the hour alone, the fill dimming from dusk into the deep of the night, and nothing of the music, so it never swings on the beat (`band.test.ts`, `main.test.ts`). It is one material, its colours in its corners and no texture, in at most 8 draws. A lit player reads against the panel by contrast in luminance along its outline: from every camera of the shoot, at night and at dusk, in every line-up and every era it played in, a quarter of the band's outline stands 3:1 from the panel, WCAG's ratio for a graphic, and a third of each player's √3:1, the panel taken as dim as the shoot's band still shows it behind the band (`outlineRead` and `PANEL_LEAST` in `band-outline.ts`). The panel goes dimmer in a quiet passage, and there the band does not read 3:1.
- The crowd's figures are lit, coloured people, faceless and never anyone's likeness: a head is a smooth egg of skin and hair, with no eyes, nose or mouth from any camera (`crowd.test.ts`). A show's crowd wears its era's clothes, by the stage's rule for a date (`DRESS` in `crowd.js`, `eraOn` in `lineup.js`): the late sixties' prints and vests, the seventies' denim, earth tones and plaid, the eighties' tie-dye and bright tees, the nineties' tie-dye, flannel and dark tees. The shader draws a top's pattern from the figure's own seed. Skin and hair come from natural ranges (`SKIN`, `HAIRS`). Trousers and shoes are plainer than tops. From every side, the lightest quarter of a figure as the eye sees it stands `APART` times lighter than its darkest, whatever its clothes are called: `drawnOf` draws how much of the figure each colour fills from twelve views, turned from the stage's bearing: four round it level, four from 0.4 rad over it, two from 0.8, one from 1.2 and one from 0.4 under it on the stage's side, which take in the eyes of the stage, the hill and the shoot's cameras (`DRAWN_VIEWS`), from the parts it wears but the thin black poles it holds up or stands by (`UNDRAWN`), standing or seated as it is, and `dressFor` keeps the colours it was dealt where they do that, and else gives it the nearest that do, one or two of its legs, its things and its top moved (`AWAY`: a top moves furthest, and a patterned top to plain or a plain one to a pattern further than to another pattern), and of the nearest the first that no one dressed before it wears whole, a step further where all of those are worn (`AWAY.spread`), and the nearest anyway where those are all worn too. Where no colours of its era bring a quarter apart, a figure keeps the margin its era's best keep: of those that bring its fifth apart, it wears one of those that bring its quarter apart from as many sides as the best and stand within `MARGIN` of its distance apart, its dealt colours where they are among them, else the nearest no one before it wears, picked by its own draw (`dressPick`); and where none bring a fifth, the same at a tenth, the share of it the test below takes (`ENDS`); and where none bring even a tenth apart, the colours that bring its tenth apart from the most sides, and of those the farthest apart. So every figure stands apart from the land or the sky seen past it: a tenth of it at least 30 % lighter or darker, in every era's clothes, on any day's gathering, at every hour, from the hill and from the stage, whatever the music does to the stage light (`crowd.test.ts`).
- The crowd dresses one of a kind: few of a crowd wear the same three colours as another of it, and few of the figures below the quarter as another such, and a figure dealt a patterned top keeps a pattern where one passes (`taken`, `AWAY`, `MARGIN`; `crowd.test.ts` pins each over `SEEDED`).
- The crowd is lit by the sky's light and the key light, as the island is, and by its own steady lights, which the night alone gives: the stage's, from where the stage light hangs, so each body has a lit side and a shadow side; the house lights, from above; and a rim on each figure's stage side, as a stage lights a crowd from behind, all of `RIM` in the deep of the night and down to `RIM_LEAST` of it where it is not dark at all (`light`, `STAGE_LIGHT` and `RIM_LIGHT` in `crowd.js`). Nothing else lights it: not the beams, not the scene's point lights (the stage light and the flame swing with the bass), and not the music's share of the sky's light, which its shader takes back out. So the light on the crowd moves with the hour alone, holds still while the figures dance, and stays on when the downgrade turns the stage light off. At its brightest the rim adds under a tenth of white's luminance to a pixel (`crowd.test.ts`, `main.test.ts`).
- Every figure of the crowd is a different person, in build, clothes, hair, what it carries and how it moves, and all of them are one merged mesh, which holds each figure's body and the parts it wears and nothing it does not (`crowd.js`). No two figures of a crowd share an outline; no colour of any is brighter than `MOST`; and whatever a figure wears or carries stays inside the reaches the parting keeps round it. `crowd.test.ts` holds each of these, and runs the shader's own text to do it: the shader is written in plain numbers so that it can. The crowd's program reads 13 of the 16 vertex attributes WebGL promises a program (`crowd.test.ts` counts them).
- The crowd's cost goes with the triangles it sends to be drawn, so it sends only what shows: under 750 a figure on a desktop and under 480 on a phone and a TV, where the one figure every figure was before was 440; and it is left out of a frame that has no figure of it in view, by a test of each figure's own sphere (`cull` in `crowd.js`; `crowd.test.ts`, `main.test.ts`). It is not instanced: an instance draws the whole figure, every part worn or not, and the shoot's renderer pays for each instance besides. The price is memory, 172 bytes to a corner, some 9 MB on a phone, 15 MB on a TV and 26 MB on a desktop.
- The rig's beams are added light. They draw in three's opaque list, before the crowd (render order 1, then 2), and write no depth, so a figure in front of a beam still hides it from every camera, and no beam lights a figure (`draw-order.test.ts`, `rig.test.ts`, `main.test.ts`).

## The trees

- A trunk is solid. A walk keeps `TREE_REACH`, 3.42 m, from the middle of every tree's foot, whichever way the walker faces, and slides round it, trying only the trunks near it (`trees.js`, `modes.js`; `modes.test.ts`, `trees.test.ts`). The reach is a bear's furthest point, its nose's tip (`SNOUT` in `bears.js`), outside the widest trunk: stood at it and facing the trunk, no corner of the visitor's bear is in the bark (`trees.test.ts`). Two reaches and half a metre fit between any two trees (`MIN_APART`, `PASS`), so a walk passes between any two.
- A tree never changes the length of the walk's camera's boom, and so never cuts the view: the camera's own place slides level round a trunk and comes down under a crown, a metre for each metre it nears one (`slide` and `ceiling` in `trees.js`, `boom` in `avatar.js`; `trees.test.ts`). It keeps what its near plane needs from bark and leaves (`eyeRoom`), and a trunk may stand between it and the bear for a moment. There are 6.5 m of air under every crown over the ground a walker stands on (`CROWN_BASE`), so the ceiling is over what the camera needs over the ground. The stage's column and the landmarks do draw the boom in, and the camera goes there without a cut (below).
- A tree's sizes are said once, in `trees.js`: how far a crown and a trunk reach, how near a walk comes, how far apart trees stand and how far off anything grows all derive from them (`CROWN_R_MAX`, `TRUNK_R_MAX`, `TREE_REACH`, `MIN_APART`, `TRUNK_ROOM`; `trees.test.ts`).
- Each tree is its own and keeps to those sizes. A kind's shape is drawn with `FORMS` morph targets, and a tree takes its own share of each by its place's seed (`formOf`): its whorls' or masses' heights and sizes, its asymmetry, its trunk's bend, its bark's grey. Each target is cut back where the targets together could carry a corner past the sizes, so no form can (`formed` in `trees.js`; `trees.test.ts`, in every form). No face turns over in any form: none faces a right angle or more from where it faces in the form of every number 0 (`trees.test.ts`). Every mass of leaves is a closed skin and every part is joined to the foot. At every corner of the box of forms, a desktop pine's outline is a cone that narrows to its leader: no band of its crown's height reaches further out than the band under it, and no clump of needles hangs from the trunk. Its bark is all trunk. From under it, sky shows through two fifths and more of the ring under its boughs' outer half, and no clump covers more than an eighth of the crown's footprint. From a walker's eye a phone's pine shows two fifths and more of its needles' lit side, 15 to 30 m off, and a desktop's, whose boughs are level to their tips, a sixth from 30 m (`trees.test.ts`).
- Where a tree may not stand is a list of rules, each with its own test (`RULES` in `trees.js`; `trees.test.ts`): the path, the bears' line, 6 m round each landmark's outline, the crowd's ground, the stage, and the ways of the tier's own cameras (`cameraWays`), the view of each landmark from `?pose=near-K` among them. A new camera or fixed view adds its way there; a tree that stands in a view moves by a rule, never the camera. A wood grows wherever the rules leave room; the groves only say whether its trees are pines or broad-crowned (`GROVES`).
- The opening is kept clear outright: from the two cameras a visitor rides, no tree stands behind the first song's landmark on to the ring, across the sight of any landmark in the frame, or in the frame within 32 m. The island has no room to keep every such view clear all along the bears' line, so those views have a cost and a tree stands in one only when no clearer place is left: a ridden camera's frame within 16 m costs most, then the sight of a landmark from one as a song begins, then close behind a landmark from its stand or as its song begins, then far behind it or between two songs (`cameraWays`, `placeTrees`; each tree's `spoils`; `trees.test.ts`). That is why a desktop draws 75 trees and not 100: of a hundred, one in six stood in a ridden camera's near frame.
- A camera's numbers are said once, in the module that flies it, and `trees.js` imports them: `BEAR_GAP` (`modes.js`), `CRANE` and `DESCENT_FROM` (`pose.js`), `boomLength` (`avatar.js`). `main.test.ts` holds `main.js` to the same ones.
- The trees are the same on every visit: 75 on a desktop and a TV, 45 on a phone (`TARGET`). A tier's are placed clear of its own cameras, with its boom's length and each number of bears its ladder shows, so a phone's are not a desktop's (`placeTrees`; `trees.test.ts`, `main.test.ts`).
- A tree takes the stage's glow no more strongly than level ground at its foot does, and a quarter of that, its bark and leaves being paler than the turf (`takesPool`'s `stands` in `island.js`, `GLOW_SHARE` in `trees.js`; `trees.test.ts`).
- The shoot takes a still from inside the pine wood and one from inside a broad-crowned grove, on a desktop and a phone, in first person with the shelves away, from the poses in `GROVE_POSES` (`.github/screenshots/assets.mjs`); `trees.test.ts` holds each pose to standing outside every trunk's reach with trees of its grove in view, so a change that moves the trees moves the pose with them.

## The walk's camera at a landmark and the stage

- The walk's camera never cuts there (#178). Where a landmark's box or the stage's column would have it, in front of the landmark or raised over it (`rise` in `boom.js`), is its goal, and its place goes to the goal no faster than three boom lengths a second, the walk's own moving of it counted in (`swift` in `avatar.js`, which says what that is in a frame). Its whole step in a frame is held to that, whatever a landmark's side, a trunk or rising ground added to it. It gathers that pace and lands (`GATHER`, `LAND`). `camera.test.ts` walks four shows, named by date, at and across every landmark and round the stage, and two more where a review found a step longer than the pace: the camera's largest move in a frame is that pace, or what the same walk moves it with nothing in its way.
- The pace is the place's. The camera is where its place is but where the trees and the crowd turn it from there, as they turn it from the walk's: a crown brings it down a metre for each metre nearer (`ceiling` in `trees.js`), so under a crown's edge the camera goes up to 1.41 times as fast as its place, and the crowd raises it at once (`over` in `crowd.js`). The place itself goes round a trunk in its way (`slide`), so the camera is never slid from one side of a trunk to the other. `camera.test.ts` holds this in the woods beside two shows' landmarks, and the crowd's raise with a stand-in for the crowd.
- On its way the place goes round a landmark or over it, never through it, and comes to rest what the eye's near plane needs from it and over the ground (`goRound` and `standOff` in `boom.js`, `eyeRoom`; `boom.test.ts`). The eye is in nothing a landmark draws inside its keep-out box unless the bear's head is in that box, and never in the stage's column (`camera.test.ts`).
- A walker who has stopped has a camera that stops: once the bear stands still the camera comes to rest, where a cut to that stand would put it. So no choice the place makes on its way may turn back from one frame to the next. A goal over a landmark or the column sends it up the side; the way round a column goes no further than the goal's bearing; where landmarks stand so close that their rooms overlap, a place they leave no way goes straight up, which is into no room; and a place the bear has pressed into a room's edge goes on round the box from there (`goRound`, `standOff`). `camera.test.ts` stops every kind of walk on seven shows and holds how long the camera takes to rest. A change to how the place goes round is tried against it, and against a sweep of stops on more shows.
- And it comes to rest one way (#194). Once the bear stands still, where the camera will rest is known: where a cut to that stand would put it. Where a landmark or the stage has a say in the goal or in that rest, the place then goes after no goal that is more than `SLACK` further from its rest than the place has been since the bear stood still, and takes no step that leaves it so (`strays` in `avatar.js`): from then on, for as long as the bear stands, it goes for its rest, and only what stands between it and there, which it goes round, takes it further from there (`boom`, `seek` and `chase`). Both halves are needed: only the goal tells of a post the boom's line crosses, which brings the place nearer its rest and nearer the bear at once, and only the step tells of a landmark that stands in the goal's way and not in the rest's. So the boom's own easing, which goes on for a second after the bear stops and moves the goal in and out as its line crosses a landmark's edge, does not move the camera in and out. With no landmark in the boom's way the camera is the boom's own, standing as walking. And the boom rises a step more over a landmark it is all but over, by the least rise that clears it and not by where its own elevation put its steps (`crest` in `boom.js`); and a goal within a hair of a room's side is on that side (`goRound`). `camera.test.ts` holds the first at every stop of its sweep, among the trees beside two shows' landmarks, at the platform's edge as the bear turns round and stands, and past a post that the boom's line only crosses; `boom.test.ts` holds the others. Not mended: looking up to the limit beside a landmark, the bear's least can press the place into the landmark's room, where it stays, metres from its rest (#191's own; three places are named in #195).
- The camera is never nearer the bear than the boom's least (`LEAST`): from the head's point where it is higher than that, and from the bear's own line where it is lower (`clear` in `avatar.js`). That is the last word on its goal and on its place, so where a landmark and the bear leave less than that between them, it is the landmark's room that gives. `camera.test.ts` tries the eye against the bear's own triangles.
- Meanwhile the landmark may stand between the camera and the bear, for under a second: `camera.test.ts` holds the share of frames and the longest run.
- For `GRACE` s after the bear's head leaves a landmark's box the boom takes no notice of that box. A walk along the path goes through every landmark on it, and the camera then passes the landmark as it would with none there.
- Under reduced motion, and on a cut, the camera is where it comes to rest (`camera.test.ts`). The crowd still raises the camera at once, by its own rule (`over` in `crowd.js`).
- A frame of the camera makes nothing: no vector, no list walked but by its indexes, no function and no object (`boom` and what it calls there, from `clear` down to `chase`, in `avatar.js`, and all of `boom.js`). `camera.test.ts` counts what a walk round a landmark makes, and reads the code for the rest.
- The tests that walk the world share one helper, `src/lib/__tests__/world-walks.ts`: a show's landmarks placed and its trees planted, a frame of a walk, the camera stepped through one, and a point tried against what is drawn.

## Motion and flashes

- Under `prefers-reduced-motion` the world holds still. It draws a frame only for an input or a change of state, or while a control is held, always at full quality (`main.js`; `main.test.ts`). The shoot takes two reduced-motion stills of the home page and two of `?pose=crowd`, and fails when a pair differs (`compare.mjs`).
- The light show's bar is WCAG 2.3.1's general and red flash thresholds: no more than 3 general flashes and 3 red flashes in any second in any 10° field, at every place it can stand. A field's flashes count where the pixels that change together cover a quarter of it or more, or where a quarter of it or more is pixels that each change more than 6 times in the same second, as under a sweeping beam; the worse of the two is the count. The count reads the bar the cautious way: a second is 61 frames, and 7 changes in it fail, so a flicker of exactly 3 a second does. A general flash is a rise and a fall of 0.1 or more in relative luminance, the darker state under 0.8; a red flash is a pair of changes of more than 20 in (R − G − B) × 320 to or from a saturated red, R/(R + G + B) of 0.8 or more. The field is a third of the viewport's width by a third of its height, the share of the screen that WCAG's 341 × 256 px is of a 1024 × 768 one, since the world fills whatever viewport it has (`scripts/flash/wcag.mjs`, and its README, which cites WCAG and says where the count departs from it; `flash-wcag.test.ts`). No CI job counts flashes. `npm run flash` counts them by render, on a machine with a GPU. A count is owed for a change to a light: the beams, the panel, the stage light, the sky, or anything that glows. A change to shapes or motion owes none. The PR text holds the counts.
- That bar replaced, on Chris's word on 2026-11-27, one of at most 6 swings of 10 % a second at any 2×2-pixel block. #128, #140, #169, #184 and the PRs before this rule hold counts by that old bar, and `npm run flash -- --blocks` still counts it beside the new one. The three rules below were set for the old bar. Each still holds, with its tests, but a later PR may loosen one with frames to show it, and owes no count.
- The trees do not move: each tree's form is set once, as it is built, and nothing hands them a time (`trees.js`; `trees.test.ts`, `main.test.ts`). Under the old bar a crown that swayed an eighth of a metre swung a block 6 times in a second where its edge crossed the bright sky at daybreak.
- The crowd dances slowly on purpose, for the old bar, under which a thin limb that passes over lit ground or the stage swings each block on its way twice as it goes and twice as it comes back. No arm goes out and back more than once in two beats, whatever it holds, a drummer's hands among them; a clap is before the chest, where the figure's own body covers it; only the bob's knees and the nod keep every beat, but that every figure's knees do as the build-up before a peak lifts the crowd; and no figure that sits raises an arm, but the one that holds a finger up, which stays up and does not move of itself. `crowd.test.ts` holds each rule for every thing a figure may carry with every way of moving, dancing, seated, rising and held still (`crowd.js`).
- The band's darkest parts, its black guitars and the shadow side of dark clothes, are as dark against the lit panel as the black band before them was, so its motion was held to the old bar, and at the hill's distance a limb is a pixel wide. What shows against the panel comes and goes once in four of the band's counts: a sway of the hips, by a hand's breadth, a stick's stroke, whose tip stands over the drummer's shoulder at its top, and a hand lifted off a keyboard. What is quicker moves over the player's own body, a hand strumming over its instrument or a singer's clapping before the chest, or against the floor, a foot tapping. The heads of those who sing stand still at their microphones: they are still parts, and the trunks sway under them. ## The ride

- The page has one way to be carried along the setlist with the bears, and one name for it, said once: `RIDE_NAME` in `src/components/world/ride.ts`, which the button, its tooltip and the legend read. `ride.test.ts` holds the code and the README's table of keys to it.
- B and F both start and end it, and starting it starts the show; Escape leaves it, and so does any walking control, which the world says with `world:mode` (`ride.ts`, `public/world/modes.js`; `ride.test.ts`, `modes.test.ts`).
- A ride settles after `IDLE_S`, ten seconds, with no input: the page strips its HUD to the settled look, hides the cursor, and marks `<main data-ride="settled">`. The settled look is the title, the line and the seek slider, the chip where one is up, and the sleep timer and Leave in the top-right corner. Awake, every input puts the settling off, a pointer's move among them; a control held down is input for as long as it is held, and a pointer that has not moved is none: the first the watch hears of a pointer only says where it is (`watchIdle`; `ride.test.ts`). The sleep timer runs in both looks, pauses the show and leaves the ride on.
- A settled page is used as it is, with a mouse as with a finger. A pointer that moves shows the cursor, which hides again `CURSOR_MS`, three seconds, after the last move, and wakes nothing. A press on a control the settled look shows does that control's work and wakes nothing, and neither does Tab, a key that only modifies another, or a key that is the focused control's own (`CONTROLS`, `quietKey`; `ride-settled.test.tsx` holds the settled page to the list of its controls). What wakes the page is a press on the bare world, and any other key (`watchIdle`; `ride.test.ts`).
- Leaving the ride by a key, Escape, B, F, or Enter or Space on Leave, with focus on Leave or the sleep timer gives the ride's button that focus, since both go with the ride; a pointer's press on Leave moves none. The cursor a settled page hides is the document's: a page that goes while settled gives it back (`createRide`; `ride.test.ts`).
- The camera has two rigs, the one that walks with the bears and a crane (`postPose`, `cranePose` in `public/world/pose.js`). It goes to the crane as the page settles and comes back only on a control that looks around, so a pointer that reaches for the page swings no view. Between the rigs it eases for `RIG_EASE_S`, three seconds, in a straight line, and never cuts (`ridePose`; `main.test.ts`). No tree's crown can reach that line on any show: of every place a tree may be tried, those the cameras' rules leave all stand clear of it (`trees.test.ts`).
- Only a ride settles. A walk lasts until the visitor leaves it, and settling moves the camera alone: the visitor's bear keeps its place in the bears' line, where the sound's listener is (#98; `modes.test.ts`, `main.test.ts`).
- A step of the shoot that takes a still of the ride says the look the still needs, awake or settled (`.github/screenshots/ride.mjs`). The shoot reads the page's mark just before the still and just after, and fails the run for a still in any other look, for a control the step presses that is not on the page, and for a state it waits for that never comes. A page that shoots the ride loads with a wait sized to its device, over twice what CI's software renderer took from a press to the end of its still (`rideIdle`; `scripts/__tests__/ride-shoot.test.ts`). The shoot uses the settled page each way: it moves the pointer over it, wakes it by a press on the world and by a key, and presses the settled chip's link, by a tap on the phone and a click on the desktops, and fails where the link is not followed (`fixed-newday-*`, `fixed-cursor-back`, `fixed-key-woken`). Every step of a ride page is taken on every device that shoots the page, so the shoot's plan names each device's stills from the page's steps; a still has one failure line, its first, and one that was not taken for a reason said there is not listed again when the run's files are held to the plan (`fileFailures`, `planFailures`). A step that says how its cursor should be has it read straight after it acts, before its still, and the reading is in the step's own line of the log (`cursorNow`): the page's line after a still comes too late for a cursor that shows for three seconds. The ride's recordings are in the shoot's one list of them (`RECORDINGS` in `.github/screenshots/recordings.mjs`), held to its rule: the press must bring the ride's state, and a recording of the camera's way to the crane or back stands, or holds Shift, until the world says the camera is there (`lean`), and fails the run when it never comes, as a settled still whose subject is the crane does (`EASE_MS`; `shoot-recordings.test.ts`, `ride-shoot.test.ts`).

## Test hooks

The test hooks, `?at=`, `?t=`, `?stats=1`, `?day=`, `?sleep=`, `?idle=`, `?lookup=`, `?pose=`, `?as=`, `?drive=`, `?still=`, `?rung=` and `?hold=`, answer only on Vercel previews. The server reads the switch, never a `NEXT_PUBLIC_` variable (`src/lib/test-hooks.ts`; `test-hooks.test.ts`). `?tier=` works anywhere.

`?pose=near-K` stands the visitor on the path beside song K's landmark, facing it (`nearStand` in `public/world/path.js`), and `?as=K:Title` builds song K's landmark as a song of that title would have it. With them the shoot takes a still of every landmark of the fixed day, then of every other kind of landmark, then of the eight kinds of standing stone, on a desktop and a phone (`.github/screenshots/near.mjs`). `scripts/__tests__/near-landmarks.test.ts` holds those titles to the builders' table and to the stones' kinds, so a new kind of landmark gets a still there. Those pages ask for `?hold=1`, which holds the landmarks' moving parts as they were built and nothing else: a ball that pulsed or a wheel that turned would be shot at another moment on every run (`public/world/main.js`; `main.test.ts`).

`?still=1`, `?rung=N` and a `?pose=` of four numbers, `X,Z,HEADING,PITCH`, are the flash counter's (`public/world/main.js`; `main.test.ts`). `?still=1` stills the figures and nothing else: the bears are hidden, the band is not moved and the crowd is posed standing still, while the rig and the lights, the sky, the sea, the tufts in the wind, the fireflies and the landmarks' moving parts move as ever, the last unless `?hold=1` holds them. `?rung=N` starts the world N rungs down its quality ladder and holds it there. The four numbers stand the visitor anywhere a walker may stand.

## The daily pick

- The site's day turns at midnight `America/New_York` (`src/lib/site-day.ts`; `site-day.test.ts`).
- A date keeps its show. `pick-schedule.test.ts` pins the opening picks and the rotation by sha256. A refresh adds new shows just before the rotation's first repeat (`addToRotation`), which moves no date before it: it changes the whole rotation's pin and `firstRepeatIndex`, never the others.
- Every show in the rotation has a recording. A show without one goes in `skipped`, with its reason (`pick-schedule.test.ts`).

## The site's address

- `SITE_URL` (`src/lib/site.ts`) is the base of every absolute link the site gives: `metadataBase`, the share link, the sitemap, `robots.txt` and the feed's links.
- A feed item's ID never changes with the site's address. It is a tag URI written out in `itemId` (`src/lib/feeds.ts`), never built from `SITE_URL` (`feeds.test.ts`).

## The maps job

- The Maps workflow (`.github/workflows/maps.yml`) runs daily at 06:20 UTC. Its `analyse` job can only read the repo. Its `publish` job checks the maps with `scripts/check-maps.mjs` and commits them to the `maps` branch, or to the branch a manual run names, never to `main`. Only the map is kept, never the audio (`scripts/analyse-show.mjs`).
- Vercel builds no deployment of `maps` (`vercel.json`).
- Maps reach `main` through a PR from a branch off `main` that merges `maps` with a merge commit and changes only `public/maps/*.json` (#117, #120).
- Each commit a PR brings from `maps`, known by ancestry and not by its author, has one parent and only adds or changes plain files named `public/maps/<show date>.json`. CI's Maps scope job checks it on every PR with `scripts/maps-scope.sh` as the PR's base has it (`ci.yml`; `scripts/__tests__/maps-scope.test.ts`).
